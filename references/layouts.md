# 排版图型手册（5 家族 / 54 型）

> 数据源 `../assets/layouts.json`。本文是人读版，冲突以 JSON 为准。
> **本册为原创整理**：只借鉴「编号 + 家族 + 画幅 + 文字层级」这种组织方式，
> 条目名称与指令文本全部重写，未复制他库内容。

## 一、为什么把排版单独拆一层

风格库回答「画成什么样」，排版回答「信息怎么摆」。两者正交：

```
画风（宋式美学 / 赛博朋克 …） ×  排版（SM-01 / IG-04 …） ×  配色（C-03 / C-17 …）
```

同一句话配不同排版，出来是「封面」还是「信息图」；同一排版换画风，出来是「杂志」还是「漫画」。
混在一起描述，模型会两边都做一半。

## 五、三条组合规则

1. **一个画面只用一个主图型**。要「封面 + 信息图」请出两张，不要在一张里叠两套版面。
2. **信息密度决定模型选型**：密度高的图型（清单卡、参数表、数字阵列）需要文字渲染能力，
   只有 Qwen-Image / MOSS-Image / FLUX / FireRed 这类能画对字；Krea 2、Z-Image-Turbo 不要碰高密度版面。
3. **画幅优先用图型给的**。图型是按画幅设计的，硬改比例会把文字区挤没。

## 六、覆盖范围怎么算

54 个基础型 × 首选画幅 × 三种信息密度 ≈ 150+ 个可直接落地的组合；
再加画风（173）与配色（36）两维，组合空间远超 170 条固定清单。
所以这里给的是**可组合的骨架**，不是一张逐条对应表——后者既无法穷举，也容易变成搬运。

## 七、新增图型：结构要求

字段清单见 `../README.md` 的「配置说明 → layouts.json」。本节只讲**怎么写才算合格**——校验脚本能查格式，查不了语义。

### 1. 编号

- 格式 `家族码-两位序号`，家族内连续递增，**删掉的号不再复用**（避免旧提示词指错）。
- 现有最大号：SM-12 / IG-12 / CM-10 / IP-08 / EC-12。新增从各自 +1 开始。
- 跨家族不共享序号：SM-13 与 IG-13 是两个东西，不要因为"都到 13"而犹豫。

### 2. 选家族

| 如果画面要解决的是… | 家族 |
|---|---|
| 让人点进来（封面、标题压图、清单） | `SM` |
| 把知识讲清楚（步骤、对比、数据） | `IG` |
| 讲故事（分镜、条漫、对白） | `CM` |
| 立角色（三视图、表情、周边） | `IP` |
| 卖东西（主图、卖点、详情） | `EC` |

拿不准时问一句：这张图**要不要写标题**？要，多半是 SM 或 IG；不要，多半是 CM 或 EC。

### 3. 画幅

- 按使用位置定，不按喜好定：小红书竖屏 `3:4`，公众号头图 `16:9`（或 `2.35:1`），长图分段 `9:16`。
- **首选画幅放数组第一位**，`--layout` 会直接取它；第二位起是"退让选项"。
- 别把 `1:1` 放首位又标 `9:16` 用途，脚本会按 `1:1` 出图。

### 4. 版面指令怎么写（最容易写坏的地方）

四条硬要求：

1. **只写方位与比例**：左/右/上/下、占几分之几、留白多少。
2. **不写画风**：不要出现"水墨""赛博""复古"，那是风格层的活。
3. **不写颜色**：颜色交给 `--color` 或风格模板，写进版面会互相打架。
4. **一句话说完**：超过 40 字模型会抓不住重点，宁可少写。

对照：

| 不合格 | 问题 | 合格 |
|---|---|---|
| 水墨风的标题在左边 | 混了画风 | 标题在左侧，占三分之一宽 |
| 高级感排版 | 无法执行 | 大字标题压上三分之一，主体中下 |
| 左边放标题，右边放图，中间加条线，底部放二维码 | 太长且塞了元素 | 左文右图，中间细分隔线 |

### 5. 信息密度怎么判

- **低**：一个主体 + 一句话，模型自由发挥也不崩。
- **中**：两个区域、三五行字，需要模型理解"分区"。
- **高**：三个以上文字块或表格——**必须选能写字的模型**（Qwen-Image / MOSS-Image / FLUX / FireRed），否则出来是乱码。

### 6. 英文指令

不是翻译，是**同构改写**：方位、比例、层级一一对应，用短句，不用从句。中文说"压在上三分之一"，英文就写 `across the top third`，不要写 `occupying approximately one-third of the upper region`。

### 7. 提交前自查

1. `id` 是否家族内唯一且连续？`family` 是否已登记？
2. `aspects[0]` 是否就是首选画幅？
3. `prompt_zh` 里有没有混进画风词或颜色词？
4. `prompt_en` 与中文是否一一对应？
5. `density` 是否与文字块数量相符？
6. `families[].count` 改了吗？`scene_map` 要不要加进去？
7. `python3 scripts/validate_library.py` 是否 0 错误？

### 8. 内容边界

本目录的条目、命名与指令均为原创整理，参考的是「编号 + 家族 + 画幅 + 文字层级」这类通用排版组织方式，不针对任何具体仓库。

新增时同样只借结构、不搬文本。若要引用外部资料，请在条目的 `use` 字段或本文件中注明来源与许可，不要把别人的条目改个名字当自己的。
